# Spec: วาระการตรวจ ปจ.2 และแหล่งข้อมูลพิกัดยก

ฉบับร่าง 20 พ.ย. 2569 (ปรับตาม Excel v3) · ใช้กับงาน Safety Inspection (แผนตรวจ ปจ.2)

ที่มาของเกณฑ์: ไฟล์ `ตาราง วาระการตรวจ ปจ.2 แยก ตามประเภทรถ v3.xlsx` (2 ชีต: ตารางวาระ 66 แถว ไม่มีแถวซ้ำ และอ้างอิงระเบียบ) · **ยึด v3** แทน v2 ทั้งหมด (สิ่งที่เปลี่ยนดูหัวข้อ 8)
ที่มาของ field: รายชื่อคอลัมน์ฐานข้อมูลจริง (`db-schema/columns.csv`, `db-schema/map-01-ข้อมูลยานพาหนะ.md`) และโค้ด `maintain-d-be` ที่ `domain/shared/vehicle/adapter/postgres_repository.go` (commit `97daab2`)

## 1. เป้าหมาย

ระบบคิดวาระการตรวจ ปจ.2 (3, 6 หรือ 12 เดือน) ของยานพาหนะแต่ละคันเอง จากประเภทย่อย ยี่ห้อ รุ่นเครน และพิกัดยก ผู้ใช้ไม่ต้องเลือกวาระ และทุกที่ที่แสดงวาระต้องบอกที่มาได้

วาระใช้ใน 3 ที่:

1. popup เลือกยานพาหนะเข้าแผน (คอลัมน์และตัวกรองวาระ)
2. ตารางยานพาหนะในแผน และ popup ผลการตรวจ
3. คำนวณวันครบกำหนดครั้งถัดไป = วันที่ตรวจที่ผ่าน + วาระ

### 2.3 ตอนนี้ API ส่งอะไรออกมา

- `domain/shared/vehicle` อ่าน `crane_name`, `crane_model` จาก `v_car_masters_2_vmsplus` (subquery `DISTINCT ON (TRIM("CarID"))` join กับ `vehicle_license_plate`)
- **ไม่มีที่ไหนในรีโปอ่าน `lift_limit` หรือ `CraneLimit`**
- `vms_mas_vehicle_mechanic` ถูกใช้แค่รวม `Cumulative_working_hours`

### 2.4 ที่ต้องแก้ฝั่ง backend (ทีม dev)

เลือกแหล่งเดียวสำหรับ ยี่ห้อ + รุ่น + พิกัดยก ไม่ปนสองแหล่ง

- **แนะนำ:** `vms_mas_vehicle_mechanic` (ผูกกับ `mas_vehicle_uid` ตรง ไม่ต้อง join ด้วยทะเบียน)
- ทางสำรอง: เพิ่ม `TRIM("CraneLimit")` ใน subquery ของ `v_car_masters_2_vmsplus` ที่มีอยู่ (แก้น้อยที่สุด แต่ join ด้วยทะเบียน)

ตัวอย่าง query (ทางแนะนำ):

```sql
LEFT JOIN (
    SELECT DISTINCT ON (mas_vehicle_uid)
        mas_vehicle_uid,
        NULLIF(TRIM(crane_name), '')  AS crane_name,
        NULLIF(TRIM(crane_model), '') AS crane_model,
        crane_number,
        lift_limit
    FROM vms_mas_vehicle_mechanic
    WHERE COALESCE(is_deleted, '0'::bit) = '0'::bit
    ORDER BY mas_vehicle_uid, lift_limit DESC NULLS LAST, updated_at DESC
) mech ON mech.mas_vehicle_uid = v.mas_vehicle_uid
```

คันเดียวมีอุปกรณ์ได้หลายแถว ตัวอย่างนี้เลือกแถวที่พิกัดยกสูงสุด เพราะวาระที่เข้มที่สุดมาจากอุปกรณ์ที่ยกได้มากที่สุด (ต้องยืนยัน ข้อ 7 แถว 3)

field ที่ต้องเพิ่มใน response รายละเอียดและค้นหายานพาหนะ (snake_case ตามแบบเดิม):

```json
{
  "vehicle_subtype": "รถเครนพิกัด 3-50 ตัน",
  "crane_brand": "TADANO",
  "crane_model": "GT-300ER",
  "crane_number": "HC-2755",
  "lift_limit_ton": 30
}
```

`lift_limit_ton` เป็น `null` เมื่อไม่มีแถวอุปกรณ์หรือไม่มีค่า

## 3. กติกาหาวาระ

ทำตามลำดับ ใช้ข้อแรกที่เจอ

| ลำดับ | เงื่อนไข | วาระ | ที่มา (`cycle_source`) |
|---|---|---|---|
| 1 | ประเภทย่อย + ยี่ห้อเครน + รุ่นเครน ตรงกับแถวในตารางเกณฑ์ | ตามแถว | `model` |
| 2 | ประเภทย่อยตรงกับแถว "ทุกยี่ห้อ ทุกรุ่น" | ตามแถว | `subtype` |
| 3 | มี `lift_limit` | 1–3 ตัน = 12 · มากกว่า 3–50 ตัน = 6 · มากกว่า 50 ตัน = 3 | `lift_limit` |
| 4 | ไม่เข้าข้อใดเลย | ไม่มีค่า | `not_found` |

การเทียบยี่ห้อ/รุ่น: ตัดช่องว่างหัวท้าย ไม่สนตัวพิมพ์เล็กใหญ่ ตัดช่องว่างและขีดกลางในรุ่นก่อนเทียบ (`TCX-55` = `TCX55` · `CMDR 4047` = `CMDR4047` · `AR-250E` = `AR250E`) · เทียบทั้งคำ ไม่เทียบขึ้นต้น (`AM855` ≠ `AM855-E81`)

แถว "ทุกยี่ห้อ ทุกรุ่น" ที่ช่องวาระว่าง (กลุ่มรถกระเช้า 3 แถวใน v3) ใช้ 12 เดือน ตามหัวตาราง "รถกระเช้า = ทุก 1 ปี" และชีตอ้างอิงระเบียบ (ต้องยืนยัน ข้อ 7 แถว 12)

รุ่นที่เจอในตารางแต่วาระเท่ากับแถวทุกยี่ห้อของประเภทย่อย ให้ `cycle_source` = `subtype` · ใช้ `model` เฉพาะรุ่นที่วาระต่างจากประเภทย่อย (AT35G · AM855) หน้าจอจะได้ชี้เฉพาะคันที่พิเศษ

**พิกัดยกน้อยกว่า 1 ตัน** ไม่มีในตารางและกฎกระทรวง ให้ถือเป็น `not_found` จนกว่าจะยืนยัน

### 4.2.1 พิกัดยกรายรุ่น (คอลัมน์ "พิกัดการยก (ตัน)" ใหม่ใน v3)

v3 ใส่พิกัดยกของรุ่นไว้ 25 รุ่น เช่น GROVE GMK2035 = 35 · TADANO TS-75ML = 7.5 · ATLAS 145.2-A2 = 3.25 · PALFINGER PK14080 = 5.87 · LIEBHERR LTM1060-3.1 = 60 · รุ่นที่เหลือ (กระเช้าทั้งหมด, HIAB ส่วนใหญ่, PALFINGER บางรุ่น ฯลฯ) ยังว่าง

- ใช้เป็น**ข้อมูลอ้างอิง**ของรุ่น ไม่ใช้คิดวาระ (กติกาลำดับ 1 เจอรุ่นก่อนอยู่แล้ว)
- ใช้เทียบกับ `lift_limit` ของรถจริงเพื่อหาข้อมูลผิด (ต่างกันมาก = แจ้งทีมข้อมูล)
- **ทศนิยมสำคัญ:** `lift_limit` เป็น integer · 3.25 ตันถูกเก็บเป็น 3 → ตกไปช่วง 1–3 ตัน (12 เดือน) แทน มากกว่า 3–50 ตัน (6 เดือน) ถ้าคันนั้นต้องใช้กติกาลำดับ 3 วาระจะผิด (ข้อ 7 แถว 1)

### 4.3 เกณฑ์กฎกระทรวง (ชีตอ้างอิงระเบียบ)

กฎกระทรวงกำหนดมาตรฐานความปลอดภัยเกี่ยวกับเครื่องจักร ปั้นจั่น และหม้อน้ำ พ.ศ. 2564 · แบบฟอร์ม ปจ.2 = ปั้นจั่นชนิดเคลื่อนที่ · ผู้ทดสอบ: วิศวกรเครื่องกลที่มีใบอนุญาต

| ประเภทงาน | พิกัดยก | วาระ |
|---|---|---|
| งานก่อสร้าง | ไม่เกิน 3 ตัน | 6 เดือน |
| งานก่อสร้าง | มากกว่า 3 ตัน | 3 เดือน |
| งานอื่น ๆ | 1–3 ตัน | 1 ปี |
| งานอื่น ๆ | มากกว่า 3–50 ตัน | 6 เดือน |
| งานอื่น ๆ | มากกว่า 50 ตัน | 3 เดือน |

กติกาลำดับ 3 ในหัวข้อ 3 ใช้แถว "งานอื่น ๆ" (ต้องยืนยัน ข้อ 7 แถว 7)

## 6. API

response ที่แสดงวาระ (รายการยานพาหนะใน popup เลือก, ยานพาหนะในแผน, ผลตรวจรายคัน):

```json
{
  "inspection_cycle": {
    "months": 12,
    "source": "model",
    "source_label": "ตามรุ่น ALTEC AM855 (รถมีอายุการใช้งานมาก)"
  }
}
```

| `source` | `source_label` ตัวอย่าง |
|---|---|
| `model` | ตามรุ่น ALTEC AM855 (รถมีอายุการใช้งานมาก) |
| `subtype` | ตามประเภท รถกระเช้าแก้กระแสไฟฟ้าขัดข้อง |
| `lift_limit` | ตามพิกัดยก 30 ตัน |
| `not_found` | ไม่พบเกณฑ์ (`months` เป็น `null`) |

หน้าจอ: ช่อง "วาระ" แสดงเดือน + บรรทัดรอง `source_label` เฉพาะ `source` ≠ `subtype` (เช่น "6 เดือน / ตามรุ่น ALTEC AM855") · คันตามประเภทแสดงแค่เดือน

ตัวกรองวาระในรายการยานพาหนะ: `cycle_months` = 3, 6, 12 และ `not_found`
